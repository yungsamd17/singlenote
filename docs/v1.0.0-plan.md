# Singlenote v1.0.0 — Release Plan

> First stable, store-ready release. Ships the “one active note” core at production quality with polished Material 3, reliable offline data, and no unfinished edges.
> Source: `main` @ `v0.2.6` (versionCode `8`). Plan owner: yungsamd17.

---

## 1. Snapshot — where we are at `0.2.6`

**Shipped:** one active note (debounced 500 ms save + `ON_STOP` flush), archive (restore/delete), share/copy, overflow menu (28 dp `surfaceContainer`, trailing icons), slide+fade NavHost, light/dark/system theme, 3 fonts × 3 sizes, pin notification, Glance widget, QS tile, DataStore prefs, Room (states `ACTIVE`/`ARCHIVED`), CI (`assembleDebug/Release + test + lint`, artifacts on push, releases on `v*`).

**Known gaps before 1.0:**
- Releases signed with debug keystore (`build.gradle.kts:32` `signingConfig debug`) — not store-ready.
- No export/import, no undo, no archive search.
- Widget single layout, no preview, no dark/dynamic variants, no resize handling.
- Notification has no actions; tile subtitle truncated but not localized.
- 2 unit tests (`NoteViewModelTest`, `TextsTest`), no instrumentation/UI/accessibility coverage.
- No auto-migration strategy tested, no backup/restore path.
- `AGENTS.md:56` still documents old overflow-menu style (plain text, no icons).
- No `CHANGELOG`, no privacy policy file, no store listing assets.

`v0.2.x → v1.0.0` must close “feels like a beta” and “not shippable to Play/F-Droid” gaps without widening the product.

---

## 2. Goals for `1.0.0`

1. **Single-note promise is rock-solid:** never lose text, never corrupt archive, recoverable via export.
2. **Feels finished:** Material 3 expressive, dynamic color, TalkBack + large-font correct, 60 fps, cold start < 700 ms mid-range.
3. **System surfaces love it:** widget and notification are reasons to keep the app.
4. **Store-ready:** properly signed, `versionCode` scheme stable, Play/F-Droid metadata, screenshots, license/privacy docs.
5. **Maintainable:** tests catch regressions, lint/detekt clean, Room migrations covered.

---

## 3. Non-goals (explicitly out for `1.0.0`)

- Multi-note notebooks, tags, folders, markdown, checklists, images, voice, sync/cloud, collaboration.
- Lock / biometric / encryption (consider `1.1.0` if demanded).
- Home-screen widget configuration activity.
- Analytics, crash SDKs, onboarding analytics.

If a request adds a second active note or a network permission, it waits until after `1.0.0`.

## 9. Release engineering — `1.0.0`

1. On `main`, set `app/build.gradle.kts:16-17`:

   ```kotlin
   versionCode = 10
   versionName = "1.0.0"
   ```

   and replace `signingConfig = signingConfigs.getByName("debug")` with `signingConfigs.create("release")` backed by `KEYSTORE_*` secrets (see `build.yml` keystore step).
2. Merge RC via PR (`release/1.0.0` → `main`), wait for CI green.
3. `git tag v1.0.0 && git push origin v1.0.0` — workflow creates `Release v1.0.0` with `app-debug.apk` + `app-release.apk` (`generate_release_notes: true`).
4. `gh release edit v1.0.0 --notes-file docs/release-notes-1.0.0.md` (curated, no AI attribution), upload screenshots.
5. If Play: promote `app-release.apk` (or `bundle` if AAB migration lands in `1.0.0` — see decision below).

## 11. Risks & mitigations

- **Signing migration breaks updates** → generate upload key once, back up offline, test update install from `0.2.6` → `1.0.0-rc1` on device.
- **Export/import edge cases** (blank notes, huge notes > 50 KB) → limit test with 10k-char note, fuzz `updatedAt`.
- **Widget stale** → add `with Glance` idling test, fallback `FallbackHint`.
- **Scope creep** → single-note guardrail: any PR adding a second active note column is rejected.
