# v1.0.0 Plan — Singlenote

Checklist for the first stable release, `v1.0.0` (`versionCode 23`, shipped
2026-11-13). Keep the “one active note” core; make it shippable.

Legend: `[x]` shipped and verified in source · `[ ]` open · `[~]` deliberately
deferred past 1.0.0.

## Decisions (2026-11-11, extended 2026-11-13)

- **Target SDK 36** is done (`compileSdk`/`targetSdk` 36); verify the Android 16
  behaviour changes on-device before the release.
- **Full backup / restore is post-1.0.0.** Archive JSON/text export stays, the app
  keeps `allowBackup="false"`, and the README states that uninstall deletes the
  active note.
- **Room schema export + migration tests** are done: `exportSchema = true`, the
  `app/schemas/` baseline is committed, and `MigrationTest` / `NoteDaoTest` run
  the real SQL on Robolectric.
- **Portrait only for 1.0.0.** Landscape, tablets and foldables are a post-1.0.0
  discussion, not a release gate; the limitation is documented in the README.
- **Tests are in scope:** add the missing suites and coverage measurement before
  claiming the ≥70% target.
- **16 KB page sizes and predictive back** are verified under SDK 36 during release
  QA. No new manifest flag is added unless the Android 16 back behaviour breaks.
- **Dependency bumps wait for the next release** (2026-11-13). The shipped set
  is the tested, green one; the held Compose/Glance/DataStore/WorkManager/
  Navigation/lifecycle bumps ride a later release instead of landing untested
  on release day. Dependabot stays on security-only until then.

## Release blockers

- [x] **Target SDK 36** — `compileSdk`/`targetSdk` are 36
  (`app/build.gradle.kts:13,23-24`). Google Play requires API 36 for new apps and
  updates since 2026-08-31. Portrait stays on phones; Android 16 ignores the lock
  at 600 dp and wider, which is documented as a 1.0.0 limitation. This unblocks
  the held `composeBom` bump.
- [x] **Room schema export + migration tests** — `exportSchema = true`
  (`data/NotesDatabase.kt:31`) and the `app/schemas/` baseline (v3) is committed
  for every future version bump. `MigrationTest` builds the v1/v2 schemas by
  hand, runs the production `MIGRATION_1_2` / `MIGRATION_2_3` through a real
  `SupportSQLiteOpenHelper.onUpgrade`, and diffs the result against a fresh
  Room v3 database; `NoteDaoTest` runs the DAO against SQLite, including the
  unique `activeSlot` guard. The absent destructive fallback stays absent.
- [~] **Test gate** — coverage is measured and gated: Kover runs in CI
  (`koverVerifyDebug`) and fails below 70 % line coverage of the app logic
  (data, util, notification rules, the three ViewModels). The scope and its
  exclusions are documented in `docs/BUILDING.md`. Archive import/export lives in
  `util/ArchiveFile.kt`, the pinned-notification rules in
  `notify/PinnedNotificationContent.kt`, both covered by tests. Still open: one
  instrumented archive flow on a device.
- [x] **Docs truth pass** — plan, TODO, README, CONTRIBUTING, AGENTS, ARCHITECTURE,
  BUILDING, ARCHIVE, TRANSLATE-APP and EDITOR-AND-SETTINGS reconciled with
  v1.0.0 and twelve languages.
- [x] **Version refs** — README roadmap and this header say `v1.0.0`; the
  release workflow step in `docs/RELEASES.md` keeps both updated on every bump.

Suggested order: schema/migration tests → test gate → store assets → tag.

## Features

- [~] **Full backup / restore** — Post-1.0.0 by decision (2026-11-11). The archive
  keeps its versioned JSON/text export; the active note and preferences stay
  unexported for now, and `allowBackup="false"` remains.
- [x] **Archive search** — Filter archived notes by text (debounced 150 ms,
  case-insensitive, trimmed). The search button appears from two notes on, Back
  closes the field before the screen, and clearing it fades the filtered-out
  notes back in.
- [~] **Swipe actions in Archive** — Deferred: Restore/Delete buttons are already
  reachable and TalkBack-friendly; a destructive swipe adds risk for little gain.
  Revisit after 1.0.0 with haptics and Undo.
- [x] **App languages** — Twelve locales (en, sk, de, es, fr, it, nl, pl, pt, ru,
  tr, zh) registered in `res/xml/locales_config.xml`, native names with the
  English name on the first line, in-place switching without activity recreation
  (#117). The device row, the "System (<language>)" hub label and the stored
  choice that survives a round trip through the device language shipped with
  v1.0.0.
- [x] **Dynamic Color** — wallpaper-color toggle (Android 12+), with preset
  accents as fallback.
- [x] **Widget** — light/dark previews, per-widget appearance and tap action,
  configurable sizes, remembered settings after removal, and an in-process render
  that survives the launcher reaping the app.
- [x] **Pinned notification** — Open and New note actions, privacy toggle,
  optional first-line title, re-post after reboot and app update. The quick
  capture archives the note on screen and keeps the pin.
- [x] **App icon picker** — default / preset accent / wallpaper color, with the
  restart warning.
- [x] **Monochrome mode** — gray color roles with the error hue preserved;
  widgets follow only when they follow the app accent.
- [x] **Archive workflow** — sort (last changed / archived / title) with persisted
  order and relative timestamps, JSON/text export, JSON import, and Undo.
- [x] **Open-source licenses** — MIT text plus every shipped component.
- [x] **Diagnostics** — hidden About gesture copies build/device/widget/crash
  details.

## Improvements

- [x] **Editor undo** — Snackbar Undo after Archive/Delete/Clear, surviving
  rotation and screen switches.
- [x] **Widget reliability** — Broadcasts coalesced to 1 s (leading + trailing,
  `NoteRepository.BROADCAST_THROTTLE_MS`), receiver uses `goAsync` on IO and logs
  failures, in-process render with a 5 s Glance fallback. Re-test on MIUI/One UI
  after any Glance bump.
- [x] **Tile polish** — 40-char locale-aware subtitle, null `qsTile` guard, and a
  TalkBack description that separates label from subtitle.
- [x] **Empty states** — Editor `hint_write_one_thing`, widget fallback hint,
  “Write a note first” tile, blank-note notification suppressed, archive empty
  copy.
- [x] **Keyboard / edge-to-edge** — `adjustResize` + `imePadding`, focus kept
  until dismissal settles, Done→Pinned transition timed independently (#118).
- [x] **Portrait lock for 1.0.0** — kept intentionally on phones
  (`AndroidManifest.xml:34`) and documented in the README. Android 16 ignores
  orientation restrictions at 600 dp and wider, so landscape/large-screen layouts
  move to the post-1.0.0 list.
- [ ] **README / store copy** — the README and the in-app copy are done; the
  store assets are still missing: phone screenshots (≥2 at 1080×1920), 7" and
  10" tablet shots, a 1024×500 feature graphic, Play short (≤80 chars) + full
  description, and F-Droid `fastlane/` metadata. Upload to the stores, then link
  from the README; never commit assets. Needs a device for the screenshots.
- [x] **Motion & tooltips** — shared `ui/Motion.kt` tokens; every icon-only button
  has a tooltip, including the editor FABs.

## Fixes

- [x] **Signing** — dedicated upload keystore via `RELEASE_KEYSTORE_*`; the debug
  key never signs releases.
- [x] **Room correctness** — transactions, the write `Mutex`, the unique
  `activeSlot` index and duplicate collapse landed. Schema export and the
  migration/DAO tests landed with them (see the blocker above).
- [ ] **Accessibility** — automated fixes landed: empty-note FABs disabled, 48 dp
  radio rows with `Role.RadioButton`, editor hint semantics, tooltips. A manual
  TalkBack pass on Android 16 is still required — it needs a device.
- [ ] **Predictive back** — under targetSdk 36 predictive back is on by default.
  Verify the NavHost back stack, the archive pair transition and dialogs on
  Android 16; opt out only if the gesture behaviour is broken. Needs a device.
- [x] **AGENTS.md drift** — overflow menu, settings, motion and archive
  transition conventions updated.

## Build / Release

- [x] **Version bump** — `versionName "1.0.0"`, `versionCode 23` (`22` was 0.5.1)
  in `app/build.gradle.kts`; the README roadmap and this header are updated in the
  same PR (see `docs/RELEASES.md`).
- [~] **Dependencies** — current: Kotlin 2.3.21, AGP 9.4.1, KSP 2.3.12, Room
  2.8.5, coroutines 1.11.0. Held past 1.0.0: `composeBom 2024.12.01`, Glance
  1.1.1, DataStore 1.1.1, WorkManager 2.7.1, Navigation 2.8.5, lifecycle 2.8.7,
  activity-compose 1.9.3, core-ktx 1.15.0. The shipped set is the tested one; the
  bump rides the next release. Dependabot stays on security-only until then.
- [x] **CI** — `lintDebug` + `lintRelease`, Gradle caching, wrapper validation,
  artifact attestation, fork signing guard, debug APKs quarantined to 1-day
  artifacts, SHA-256 of both release APKs logged.
- [ ] **16 KB page sizes** — confirm the release APK aligns 16 KB ELF segments
  (Play requires it for apps targeting 35+; pure Kotlin should pass, but verify
  with `zipalign -c -P 16` or the Play pre-launch report). Checked against the
  published `v1.0.0` APK after the tag; the app ships no native libraries.
- [ ] **Tag release** — `git tag v1.0.0 && git push origin v1.0.0`; `release.yml`
  validates the tag against `main` and `versionName`, then publishes
  `singlenote-v1.0.0-debug.apk` + `singlenote-v1.0.0-release.apk`. The tag
  follows the merge of the version-bump PR.

## Quality

- [~] **Tests** — 202 JVM tests pass locally (the suite runs on a 2-core ARM
  host). The coverage tooling is in place: Kover measures the app logic and CI
  fails below 70 % line coverage (the measured value is in the PR that added the
  gate). `PinNotification` and the archive import/export are covered. Still open:
  one archive-flow instrumentation test (`androidTest/` is still missing despite
  the configured runner) — it needs a device.
- [ ] **Manual QA** — Android 10, 15 and 16 (the 1.0 floor and the current Play
  requirement), small phone and large system text, TalkBack,
  type → background → foreground, archive → undo, archive export → clear →
  import, theme/language/accent surviving restart and process death. Portrait only
  for 1.0.0; tablet/foldable checks move with the post-1.0.0 layout work. Needs a
  device.
- [ ] **Performance** — cold start < 700 ms mid-range, no StrictMode violations
  (add a debug-only StrictMode harness), no `SecurityException` on notify, and
  bounded widget repaint while typing.

## Out of scope for 1.0.0

Multiple active notes, tags/folders, markdown/checklists, images/voice, cloud
sync, biometric lock, and analytics.

## Post-1.0.0 (decided 2026-11-11)

- Full backup / restore of the active note, archive and preferences.
- Landscape, tablet and foldable layouts for 600 dp and wider; Android 16 already
  ignores the portrait lock there. Revisit the lock once the layouts pass QA.
- Swipe actions in the archive (with haptics and Undo).
- Archive search, if it slips out of 1.0.0.
